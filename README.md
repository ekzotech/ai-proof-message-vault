# AI-Proof Message Vault

Капсула времени для текста. Порядок разработки и критерии приёмки описаны в [плане реализации](PLAN.md).

## Локальный запуск на Windows

Нужны PHP 8.4, Composer 2, Node.js 24 и npm. Для локальной базы используется SQLite.

Проверьте инструменты из корня проекта:

```powershell
.\scripts\check-platform.ps1
```

Если PHP и Composer распакованы отдельно, добавьте каталог с `php.exe` в `PATH` текущего сеанса и передайте путь к PHAR:

```powershell
$env:Path = "C:\Tools\php;$env:Path"
.\scripts\check-platform.ps1 -ComposerPhar C:\Tools\composer.phar
```

Для каждой команды `composer` ниже с переносимым PHAR используйте `php C:\Tools\composer.phar`.

```powershell
composer install
if (!(Test-Path .env)) {
    Copy-Item .env.example .env
    php artisan key:generate
}
composer db:init
npm.cmd ci
npm.cmd run build
php artisan serve
```

Откройте <http://127.0.0.1:8000>. Проверка доступности находится по адресу <http://127.0.0.1:8000/up>.

`composer db:init` создаёт локальный файл SQLite при первом запуске и применяет новые миграции при повторных вызовах. Файл базы и `.env` исключены из Git.

Для русских писем и сообщений валидации укажите `APP_LOCALE=ru` в существующем `.env`. Для ссылок в письмах `APP_URL` должен совпадать с адресом, по которому вы открываете приложение. Локальный `MAIL_MAILER=log` пишет письма в журнал. Для доставки настройте почтовый транспорт и адрес отправителя.

```powershell
php artisan test
composer lint
composer audit:locked
```

## Как читать проверку извлечения

Читательские страницы запрашивают исключение из индекса через `X-Robots-Tag`. `CAPSULE_REQUEST_NO_AI=true` добавляет `noai` и `noimageai` для роботов, которые их поддерживают. Эти директивы добровольны для получателя.

В кабинете сохраните черновик и откройте его предпросмотр. Щадящий режим использует омоглифы и невидимые пробелы. Экспериментальный дополнительно переставляет символы коротких групп слов в HTML. Переключатель режима обрабатывает ту же сохранённую версию текста.

Проверка сравнивает исходник и текст, извлечённый из HTML. Для каждого способа обе строки проходят одинаковую нормализацию. «Совпало» означает равенство в рамках этого способа. Например, для слова `hello` со вставленным U+200B чтение DOM даёт расхождение, а очистка пробелов восстанавливает совпадение. Сведение омоглифов сравнивает каноническое написание, поэтому совпадение не подтверждает восстановление исходных кодовых точек.

Фикстуры в `tests/Fixtures/CapsuleSamples.php` покрывают русский, английский, смешанный текст, ссылки, эмодзи и направление чтения. Проверки можно повторить командой `php artisan test --filter=TextExtractionTest`. Обработка меняет результаты отдельных способов извлечения. Публичное послание можно восстановить или переписать, и сервис не может подтвердить, кто написал текст.

## Хранение и восстановление

SQLite хранит заголовки и расписание, зашифрованный исходный текст и зашифрованные сегменты публикации. Токен читательской ссылки хранится зашифрованным для владельца. При запросе ссылки приложение ищет её по хешу. Отзыв закрывает ссылку, а удаление убирает черновик и связанный снимок из рабочей базы. Уже сделанные копии и резервные копии живут по своим срокам хранения.

Для согласованной резервной копии SQLite остановите приложение и фоновые процессы, затем скопируйте файл БД. Ключ `APP_KEY` храните отдельно в защищённом хранилище. Для репетиции восстановления поднимите изолированный экземпляр с копией базы, исходным ключом и отключённой отправкой почты. Проверьте миграции командой `php artisan migrate:status`, войдите тестовым автором и откройте его черновик и читательский снимок. Проверку совместимости со старым ключом можно повторить командой `php artisan test --filter=CapsuleKeyRecoveryTest`.

При плановой ротации настройте новый `APP_KEY`, а предыдущий добавьте в `APP_PREVIOUS_KEYS`. Старый ключ нужен до перешифрования оставшихся записей и истечения срока их резервных копий. Обновите кеш конфигурации и перезапустите процессы после смены ключей. В production отключите `APP_DEBUG` и исключите реальные ссылки и тела запросов из access-логов прокси и внешней телеметрии.

## Проверка вёрстки и клавиатуры

Лендинг и открытая капсула проверены в Chrome на ширинах 320, 390, 768 и 1440 px. Для лендинга дополнительно проверено отсутствие обрезания при масштабе CSS 200%. На 320 px проверены переход к содержимому с клавиатуры, фокус на ошибках входа, работа редактора и возврат фокуса после закрытия диалога отзыва по Escape.

## Браузерные тесты Dusk

Для запуска нужен Chrome и ChromeDriver той же версии. Соберите ресурсы и запустите отдельный тестовый сервер:

```powershell
php artisan dusk:chrome-driver --detect
npm.cmd run build
composer dusk
```

Если переносимый PHP на Windows не доверяет центру сертификации при загрузке, скачайте соответствующий ChromeDriver из [Chrome for Testing](https://googlechromelabs.github.io/chrome-for-testing/) и поместите распакованный `chromedriver.exe` в `vendor/laravel/dusk/bin/chromedriver-win.exe`. Тестовый запуск использует временную SQLite, случайный ключ и отдельный порт. Почта остаётся в памяти тестового процесса.

При локальном сбое Dusk оставляет снимки и HTML в `tests/Browser`. В GitHub Actions выполняются те же тесты, а отчёт содержит количество файлов диагностики.

## Развёртывание и откат

Укажите корень веб-сервера `public/` и включите HTTPS. В отдельном staging-окружении используйте собственные SQLite и `APP_KEY`. Для публичного запуска настройте `APP_ENV=production`, `APP_DEBUG=false`, канонический `APP_URL`, реальный почтовый транспорт и доступ на запись только в необходимые каталоги Laravel и БД. Для staging с HTTPS задайте `SESSION_SECURE_COOKIE=true` явно. Храните ключ вне репозитория и сохраняйте его между релизами.

```sh
composer install --no-dev --prefer-dist --no-interaction --optimize-autoloader
npm ci
npm run build
php artisan migrate --force
php artisan config:cache
php artisan route:cache
php artisan view:cache
```

Сначала проверьте `/up` и `/ready`. Первый маршрут проверяет запуск Laravel, второй проверяет чтение из базы и отдаёт 503 при недоступности. В staging проверьте вход, создание черновика и обе стороны даты открытия. Для отката остановите трафик и фоновые процессы, восстановите предыдущий релиз с его lock-файлами и согласованную резервную копию БД, сохранив её ключ. Пересоберите кеши и повторите HTTP-проверки. В локальной репетиции использовалась отдельная SQLite.

## Сценарии автора и читателя

1. Зарегистрируйтесь и подтвердите почту. В профиле выберите часовой пояс для ввода даты открытия.
2. Создайте черновик, добавьте заголовок и текст, выберите будущую дату. Сохраните изменения и откройте предпросмотр. Переключите режим обработки и раскройте результаты проверки извлечения.
3. Проверьте время и режим, подтвердите заявление об авторстве и запечатайте капсулу. Откройте опубликованную капсулу в кабинете и скопируйте ссылку.
4. По ссылке до открытия видна дата в UTC. После открытия читатель может переключиться на обычный текст для скринридера.
5. В кабинете можно отозвать ссылку или удалить капсулу. Отзыв и удаление не отзывают уже сделанные копии.

Для знакомства с четырьмя состояниями в локальной базе можно явно запустить `php artisan vault:demo`. Команда создаст отдельный демо-аккаунт и выведет его пароль и синтетические ссылки. Используйте `--json`, чтобы прочитать результат скриптом.
